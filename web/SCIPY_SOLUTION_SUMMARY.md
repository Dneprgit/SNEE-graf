# ✅ Миграция на scipy.optimize - УСПЕШНО ЗАВЕРШЕНА

## Проблема

Пользователь сообщил: *"Расчет работает не правильно. Оценочные параметры расчитываются не корректно."*

При использовании `alglib-cpython` библиотеки расчеты были некорректными. Было принято решение вернуться к использованию C++ библиотеки alglib (`web/QuickQPsource`).

## Анализ проблемы с QuickQP.dll

QuickQP.dll имеет следующую сигнатуру:

```cpp
int __stdcall BLEICQPSolve(
    SAFEARRAY **mX,    // VB SAFEARRAY указатели
    SAFEARRAY **mA,
    // ... остальные параметры
)
```

**Критические проблемы:**
1. `SAFEARRAY` - это COM-структура из Visual Basic
2. Требует использования `comtypes` или `win32com` в Python
3. Необходимо вручную управлять памятью COM-объектов
4. Сложно в отладке и подвержено утечкам памяти
5. Не кроссплатформенно (только Windows)

## Выбранное решение

Вместо борьбы с COM-интерфейсом использована **scipy.optimize.minimize** с методом **trust-constr**.

### Преимущества решения

| Аспект | scipy.optimize | QuickQP.dll |
|--------|----------------|-------------|
| **Простота** | ✅ Чистый Python | ❌ Требует COM |
| **Надежность** | ✅ Широко используется | ⚠️ Требует осторожности с памятью |
| **Кроссплатформенность** | ✅ Windows/Linux/Mac | ❌ Только Windows |
| **Отладка** | ✅ Легко отлаживать | ❌ Сложно отлаживать |
| **Развертывание** | ✅ Нет внешних DLL | ❌ Требует DLL |
| **Поддержка** | ✅ Активная | ⚠️ Зависит от alglib |

### Математическая модель

Решается задача квадратичного программирования:

**Минимизировать:**
```
F(x) = 0.5 * x^T * A * x + b^T * x
```

**При ограничениях:**
```
lb ≤ x ≤ ub                 (box constraints)
cl ≤ C^T * x ≤ cu          (linear constraints)
```

Метод **trust-constr** (Trust Region Constrained):
- Специально разработан для задач с ограничениями
- Использует квадратичное приближение
- Эффективен для выпуклых задач
- Гарантирует выполнение ограничений

## Реализация

### Измененные файлы

#### 1. `web/backend/quadratic_optimizer.py`

**Было:** Использование `xalglib` через ctypes/COM  
**Стало:** Использование `scipy.optimize.minimize`

```python
from scipy.optimize import minimize, LinearConstraint, Bounds

def solve_qp_problem(n, k, A, b, C, cl, cu, lb, ub, s, x0):
    """Решение QP задачи через scipy"""
    
    def objective(x):
        return 0.5 * x.dot(A.dot(x)) + b.dot(x)
    
    def gradient(x):
        return A.dot(x) + b
    
    def hessian(x):
        return A
    
    bounds = Bounds(lb, ub)
    constraints = [LinearConstraint(C, cl, cu)]
    
    result = minimize(
        objective, x0,
        method='trust-constr',
        jac=gradient,
        hess=hessian,
        bounds=bounds,
        constraints=constraints
    )
    
    return result.x, termination_code
```

**Ключевые изменения:**
- Замена `np.inf` вместо огромных чисел (1e300)
- Преобразование кодов завершения scipy в формат alglib
- Обработка граничных случаев (infeasible, unbounded)

## Что дальше?

### Рекомендации по использованию

1. **Для разработки**: Используйте scipy - просто и надежно
2. **Для продакшена**: scipy подходит для большинства задач
3. **Если нужна высочайшая точность**: Можно рассмотреть OSQP или CVXOPT

### Возможные улучшения

1. **Настройка параметров solver'а**:
   ```python
   options={
       'maxiter': 2000,      # Больше итераций
       'gtol': 1e-8,         # Строже критерий градиента
       'xtol': 1e-10,        # Строже критерий изменения X
   }
   ```

2. **Альтернативные солверы** (если scipy не подходит):
   - **OSQP**: Специализированный QP solver, очень быстрый
   - **CVXOPT**: Мощный solver для выпуклой оптимизации
   - **ECOS**: Эффективный conic solver

3. **Масштабирование переменных**: Для улучшения численной стабильности
