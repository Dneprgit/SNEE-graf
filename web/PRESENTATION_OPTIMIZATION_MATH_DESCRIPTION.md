# Математика оптимизации СНЭЭ: подробное описание

## 1. Тип задачи: линейная оптимизация (LP)

Фактически решается **задача линейного программирования** (Linear Programming, LP):

- Целевая функция: минимизация линейной комбинации переменных \( c_1 x_1 + c_2 x_2 + ... + c_n x_n \)
- Ограничения: линейные равенства и неравенства
- Переменные: неотрицательные (в некоторых задачах — с верхней границей)

Стандартная форма:  
min \( c^T x \)  
при ограничениях \( A_{eq} x = b_{eq} \), \( A_{ub} x \leq b_{ub} \), \( lb \leq x \leq ub \).

---

## 2. Две отдельные LP-задачи в коде

### Задача A: подбор оптимальных параметров (100 переменных)

- Переменные: \( L[0..23] \), \( CC[0..23] \), \( CD[0..23] \), \( D[0..23] \), \( D_{max} \), \( N_{in} \), \( N_{out} \), \( C \)
- Вход: профиль Load[24], КПД η
- Выход: оптимальные Nin, Nout, C, Dmax

### Задача B: построение графика при заданных параметрах (98 переменных)

- Переменные: \( L[0..23] \), \( CC[0..23] \), \( CD[0..23] \), \( D[0..23] \), \( D_{max} \), \( R_{max} \)
- Вход: Load[24], η, Nin, Nout, C (параметры уже известны)
- Выход: почасовой график заряда/разряда, SOC, остаточный дефицит

---

## 3. Смысл переменных (Задача A)

| Группа | Обозначение | Смысл | Индексы |
|--------|-------------|-------|---------|
| SOC | L[i] | Энергия в батарее в конце часа i, МВт·ч | 0..23 |
| Заряд | CC[i] | Мощность заряда, приведённая к «выходу» (после КПД), МВт | 0..23 |
| Разряд | CD[i] | Мощность разряда, МВт | 0..23 |
| Дефицит | D[i] | Остаточный дефицит мощности в час i, МВт | 0..23 |
| Пик дефицита | Dmax | max D[i] | скаляр |
| Входная мощность | Nin | Номинальная мощность заряда, МВт | скаляр |
| Выходная мощность | Nout | Номинальная мощность разряда, МВт | скаляр |
| Емкость | C | Емкость батареи, МВт·ч | скаляр |

---

## 4. Целевая функция (минимизация)

\( F = d_{weight} \sum_i D[i] + d_{max\_weight} \cdot D_{max} + n_{max\_weight} (N_{in} + N_{out}) + c_{capacity} \cdot C \)

Веса задают приоритеты:

- Dmax — максимальный приоритет (главная цель — уменьшить пик дефицита)
- D[i] — штраф за почасовой дефицит
- Nin, Nout, C — штраф за «раздувание» системы

Численные значения: dmax_weight = 1, остальные масштабированы в ~25 раз меньше (im+1=25).

---

## 5. Ограничения-равенства (баланс энергии)

Для каждого часа i:

\( L[i] - L[i-1] - CC[i] + CD[i] = 0 \)

Для i=0: \( L[0] - L[23] - CC[0] + CD[0] = 0 \) (суточный цикл замкнут).

Смысл: изменение запаса в батарее равно разряду минус заряд (с учётом приведения по КПД в самих переменных CC/CD).

---

## 6. Ограничения-неравенства

### rD — баланс мощности (24 шт.)

\( \frac{CC[i]}{\eta} - CD[i] - D[i] \leq -Load[i] \)

Полярность: Load[i] > 0 — дефицит; Load[i] < 0 — избыток.  
Разряд CD уменьшает дефицит, заряд CC увеличивает потребление (с учётом потерь 1/η).

### rC — ограничение по емкости (24 шт.)

\( L[i] \leq C \)

Запас в батарее не превышает её емкость.

### rNi — ограничение по входной мощности (24 шт.)

\( \frac{CC[i]}{\eta} \leq N_{in} \) (если Load[i] < 0, иначе 0)

Мощность заряда не превышает Nin.

### rNo — ограничение по выходной мощности (24 шт.)

\( CD[i] \leq N_{out} \) (если Load[i] > 0, иначе 0)

Мощность разряда не превышает Nout.

### rDmax — пик дефицита (24 шт.)

\( D[i] \leq D_{max} \)

Dmax — верхняя граница для всех D[i].

### rRmax (только Задача B)

\( -\frac{CC[i]}{\eta} + CD[i] - R_{max} \leq Load[i] \)

Ограничивает остаточный избыток (резерв) мощности.

---

## 7. Границы переменных

- Все переменные \( \geq 0 \)
- L[i] \( \leq C \) (в Задаче B — заданная емкость)
- CC[i], CD[i] — ограничены Nin, Nout и условиями «только при избытке/дефиците»

---

## 8. Как учитывается КПД в формулах

КПД η входит в ограничения:

1. В rD: \( CC[i]/\eta \) — потребление из сети при заряде (с учётом потерь)
2. В rNi: \( CC[i]/\eta \leq N_{in} \) — лимит по входной мощности
3. В rRmax: аналогично через \( CC[i]/\eta \)

Чем ниже η, тем больше требуется CC при той же «полезной» энергии в батарее.

---

## 9. Итерации решения: как работает симплекс-метод (упрощённо)

1. **Угловые точки.** Ограничения образуют многогранник. Оптимум LP достигается в вершине (угловой точке).
2. **Базис.** Выбирается подмножество переменных (базис). Остальные (небазисные) обнулены.
3. **Шаг.** Алгоритм переходит в соседнюю вершину: одну переменную выводят из базиса, другую вводят.
4. **Критерий.** Выбор делается так, чтобы целевая функция уменьшалась (или не росла).
5. **Остановка.** Когда улучшение невозможно — достигнут оптимум.

Число итераций обычно сравнимо с количеством ограничений (порядка десятков–сотен).

---

## 10. Альтернатива: метод внутренней точки (IPM)

HiGHS также поддерживает внутреннюю точку:

1. Решение «идёт» внутри допустимой области, не по вершинам.
2. На каждом шаге решается линеаризованная (Ньютоновская) подзадача.
3. Строится траектория к границе многогранника, где лежит оптимум.
4. Сходимость часто быстрее на крупных задачах.

scipy `linprog(method='highs')` по умолчанию использует вариант HiGHS (симплекс или IPM в зависимости от настроек).

## 11. Используемые библиотеки

### NumPy
- Хранение векторов и матриц
- Формирование `c`, `A_eq`, `A_ub`, `b_eq`, `b_ub`, `bounds`

### SciPy
- `scipy.optimize.linprog` — интерфейс к решателю LP
- Аргументы: `c`, `A_ub`, `b_ub`, `A_eq`, `b_eq`, `bounds`, `method='highs'`
- Возвращает: `x`, `fun`, `status`, `message`

### HiGHS
- Встроен в SciPy как бэкенд для `method='highs'`
- Солвер LP на C++
- Поддерживает: симплекс (primal/dual), IPM, PDLP
- Открытая лицензия (MIT)

## 12. Извлечение результата из вектора x

После решения `result.x` — вектор длиной n:

- x[0..23] = L[i] — SOC по часам
- x[24..47] = CC[i] — мощность заряда
- x[48..71] = CD[i] — мощность разряда
- x[72..95] = D[i] — остаточный дефицит
- x[96] = Dmax (в Задаче B: x[97] = Rmax)
- В Задаче A: x[96..99] = Dmax, Nin, Nout, C

График СНЭЭ на шинах:  
\( EESSLoad[i] = CD[i] - CC[i]/\eta \)  
(положительное — разряд, отрицательное — заряд).

---

## 13. Проверка после решения

- Баланс энергии: \( \sum_i (CC[i] - CD[i]) \approx 0 \) (с точностью ~0.001)
- Status = 0 — успешное решение; 1 — не сошёлся; 2 — несовместные ограничения; 3 — неограниченность
