## 🔍 Математическая корректность

### Ограничения (проверить при запуске)

- [ ] **Баланс энергии (rL)**
  ```
  Для каждого часа i: dL[i] - dL[i-1] - CC[i] + CD[i] = 0
  ```

- [ ] **Баланс мощности (rD)**
  ```
  Для каждого часа i: -CC[i]/η + CD[i] + D[i] ≥ SystemLoad[i]
  ```

- [ ] **Ограничение резерва (rDmin)**
  ```
  Для каждого часа i: CC[i]/η - CD[i] + Rmax ≥ -SystemLoad[i]
  ```

- [ ] **Ограничение дефицита (rDmax)**
  ```
  Для каждого часа i: -D[i] + Dmax ≥ 0
  ```

### Границы переменных (проверить при запуске)

- [ ] **Энергия в батарее**: 0 ≤ dL[i] ≤ dblCapacity
- [ ] **Мощность заряда**: 0 ≤ CC[i] ≤ dblNIn * η
- [ ] **Мощность разряда**: 0 ≤ CD[i] ≤ dblNOut
- [ ] **Дефицит по часам**: 0 ≤ D[i] ≤ ∞
- [ ] **Максимумы**: 0 ≤ Dmax, Rmax ≤ ∞

### Баланс заряд-разряд (проверить при запуске)

- [ ] **Суточный баланс**
  ```
  |Σ(CC[i] - CD[i])| < 0.001 МВтч
  ```

## 📝 Известные особенности

1. **Полярность**: В QP положительное = дефицит (противоположно первому варианту)
2. **Индексация**: Python использует индексацию с 0, VB с 1
3. **Циклическая связь**: dL[0] связан с dL[23]
4. **Scipy vs Alglib**: Используется scipy.optimize вместо alglib DLL
5. **Коды завершения**: Успешные коды 1,2,4,5,7,8 (не только 2 и 4)

## 🐛 Отладка

### Если оптимизация не сходится

1. Проверить входные данные (24 значения, корректные числа)
2. Проверить параметры СНЭЭ (положительные, разумные значения)
3. Увеличить maxiter в minimize (по умолчанию 2000)
4. Проверить масштаб чисел (не должно быть Infinity)

### Если баланс нарушен

1. Проверить формулу извлечения: dblEENSLoad[i] = CD[i] - CC[i]/η
2. Проверить ограничения rL (баланс энергии)
3. Проверить циклическую связь (i=0 → i-1=23)

### Если SOC выходит за границы

1. Проверить границы: 0 ≤ dL[i] ≤ dblCapacity
2. Проверить ограничение rC (емкость)
3. Проверить начальное приближение x0
