# QP Алгоритм расчета диспетчерского графика СНЭЭ

## Обзор

Реализован алгоритм квадратичной оптимизации (QP) для расчета оптимального диспетчерского графика работы Системы Накопления Электрической Энергии (СНЭЭ).

Алгоритм переносен из VB кода (функция `GetEESSOptimalLoad` в файле `web/backend/VB/Module1.bas`) и использует библиотеку `scipy` для решения задачи квадратичной оптимизации.

## Математическая постановка задачи

### Переменные оптимизации (n = 98)

- `x[0..23]` = `dL[i]` - уровень энергии в батарее по часам (МВтч)
- `x[24..47]` = `CC[i]` - почасовой заряд (МВт)
- `x[48..71]` = `CD[i]` - почасовой разряд (МВт)
- `x[72..95]` = `D[i]` - дефицит по часам (МВт)
- `x[96]` = `Dmax` - максимальный дефицит мощности (МВт)
- `x[97]` = `Rmax` - максимальный резерв мощности (МВт)

### Целевая функция

```
F(x) = 0.5 * x' * A * x + b' * x → min

где:
A = diag(0.00000001) - диагональная матрица для регуляризации
b[0..71] = 0
b[72..95] = 0.04  (веса для дефицита по часам)
b[96] = 1.0       (вес для максимального дефицита)
b[97] = 0.0016    (вес для резерва)
```

### Ограничения (k = 96)

1. **rL** - баланс энергии (24 ограничения):
   ```
   dL[i] - dL[i-1] - CC[i] + CD[i] = 0
   ```
   Обеспечивает непрерывность уровня энергии в батарее.

2. **rD** - баланс мощности (24 ограничения):
   ```
   -CC[i]/η + CD[i] + D[i] >= Load[i]
   ```
   Гарантирует покрытие нагрузки системы с учетом дефицита.

3. **rDmin** - резерв (24 ограничения):
   ```
   CC[i]/η - CD[i] + Rmax >= -Load[i]
   ```
   Обеспечивает резерв мощности для поглощения избытков.

4. **rDmax** - дефицит по часам (24 ограничения):
   ```
   -D[i] + Dmax >= 0  =>  Dmax >= D[i]
   ```
   Определяет максимальный дефицит.

### Границы переменных

- `dL[i]`: `0 <= dL[i] <= Capacity`
- `CC[i]`: `0 <= CC[i] <= Nin * η`
- `CD[i]`: `0 <= CD[i] <= Nout`
- `D[i]`, `Dmax`, `Rmax`: `0 <= x <= ∞`

### Входные данные

- `load_profile[24]` - суточный профиль баланса мощности (МВт)
- `efficiency` (η) - КПД цикла заряда-разряда (0-1)
- `rated_power_in` (Nin) - номинальная входная мощность (МВт)
- `rated_power_out` (Nout) - номинальная выходная мощность (МВт)
- `rated_capacity` - емкость батареи (МВтч)

### Выходные данные

- `eess_load[24]` - оптимальный диспетчерский график работы СНЭЭ (МВт)
  ```
  eess_load[i] = CD[i] - CC[i]/η
  ```
  Положительные значения - разряд (выдача в сеть)
  Отрицательные значения - заряд (потребление из сети)

- Дополнительные параметры (доступны через `_last_qp_solution`):
  - `energy_available[24]` - уровень энергии в батарее (МВтч)
  - `charge[24]` - почасовой заряд (МВт)
  - `discharge[24]` - почасовой разряд (МВт)
  - `deficit_hourly[24]` - дефицит по часам (МВт)
  - `deficit_max` (Dmax) - максимальный дефицит (МВт)
  - `reserve_max` (Rmax) - максимальный резерв (МВт)

## Изменения в коде

### 1. Класс `EnergyStorageCalculator_qp`

**Файл:** `web/backend/energy_storage_calculator.py`

#### Обновленный конструктор

Добавлена поддержка асимметричных входной и выходной мощностей:

```python
def __init__(self, rated_power_mw: float, rated_capacity_mwh: float, efficiency: float, 
             rated_power_in_mw: float = None, rated_power_out_mw: float = None):
```

- `rated_power_in_mw` (Nin) - номинальная входная мощность
- `rated_power_out_mw` (Nout) - номинальная выходная мощность

Если не указаны, используется симметричное значение `rated_power_mw`.

#### Метод `calculate_dispatch_schedule_qp`

Полностью переписан с использованием QP алгоритма:

- Использует `scipy.optimize.minimize` с методом `'trust-constr'`
- Реализует все 96 ограничений из VB кода
- Возвращает оптимальный график работы СНЭЭ
- Сохраняет дополнительные параметры решения в `_last_qp_solution`

#### Метод `get_summary`

Обновлен для возврата дополнительных параметров QP:

- `qp_deficit_max_mw` (Dmax) - если доступен
- `qp_reserve_max_mw` (Rmax) - если доступен

### 2. API

**Файл:** `web/backend/main.py`

Эндпоинт `/api/v1/calculate-qp` автоматически использует новый QP алгоритм без изменений в интерфейсе.

## Использование

### Через API

```bash
curl -X POST "http://localhost:8002/api/v1/calculate-qp" \
  -H "Content-Type: application/json" \
  -d '{
    "load_profile": [27, 38, 84, 137.5, 21.3, -115.2, ...],
    "rated_power_mw": 200,
    "rated_capacity_mwh": 500,
    "efficiency": 0.95
  }'
```

### Через Python

```python
from energy_storage_calculator import EnergyStorageCalculator_qp

# Создание калькулятора с асимметричными мощностями
calculator = EnergyStorageCalculator_qp(
    rated_power_mw=200,          # Обратная совместимость
    rated_capacity_mwh=500,
    efficiency=0.95,
    rated_power_in_mw=200,       # Входная мощность (Nin)
    rated_power_out_mw=180       # Выходная мощность (Nout)
)

# Расчет диспетчерского графика
load_profile = [27, 38, 84, ...]  # 24 значения
eess_schedule = calculator.calculate_dispatch_schedule_qp(load_profile)

# Получение сводной информации
summary = calculator.get_summary(load_profile, eess_schedule)

# Доступ к дополнительным параметрам QP
if hasattr(calculator, '_last_qp_solution'):
    qp_sol = calculator._last_qp_solution
    print(f"Dmax: {qp_sol['deficit_max']:.2f} МВт")
    print(f"Rmax: {qp_sol['reserve_max']:.2f} МВт")
```

## Проверка результатов

Для проверки корректности реализации сравните результаты с VB кодом:

1. **Уровень энергии в батарее** (`dL[i]`) - должен соответствовать ячейкам B10:Y10 в Excel
2. **График нагрузки СНЭЭ** (`eess_load[i]`) - должен соответствовать ячейкам B11:Y11 в Excel
3. **Максимальный дефицит** (`Dmax`) - должен соответствовать ячейке B13 в Excel
4. **Максимальный резерв** (`Rmax`) - должен соответствовать ячейке B14 в Excel

### Критерий баланса

Сумма заряда должна быть равна сумме разряда (с точностью до 0.001 МВтч):
```
Σ(CC[i]) ≈ Σ(CD[i])
```

Это проверяется автоматически внутри метода `calculate_dispatch_schedule_qp`.

## Ключевые отличия от water-filling алгоритма

| Аспект | Water-filling | QP оптимизация |
|--------|---------------|----------------|
| Метод | Эвристический | Точная оптимизация |
| Переменные | Неявные уровни | 98 явных переменных |
| Ограничения | Упрощенные | 96 точных ограничений |
| Результат | Приближенный | Оптимальный |
| Дополнительные параметры | Нет | Dmax, Rmax, почасовые D[i] |
| Асимметричные Nin/Nout | Не поддерживается | Полная поддержка |

```bash
pip install -r requirements.txt
```

## Примечания

1. Алгоритм гарантирует оптимальное решение при корректных входных данных
2. Время работы: обычно < 1 сек на стандартном ПК
3. При несходимости оптимизации выдается предупреждение, но результат все равно возвращается
4. Параметр `rated_power_mw` сохранен для обратной совместимости
