# Реализация двух вариантов алгоритмов расчета СНЭЭ

## Обзор

Проект был расширен для поддержки двух независимых вариантов расчета диспетчерского графика СНЭЭ:

1. **Water-Filling (WF)** - существующий алгоритм
2. **Квадратичная оптимизация (QP)** - новый вариант для дальнейшей доработки

## Структура изменений

### Frontend

#### 1. Переключатель алгоритмов
- **Файл**: `web/frontend/src/components/Hero.jsx`
- **Описание**: Добавлен переключатель для выбора между алгоритмами WF и QP
- **Расположение**: В секции Hero (общая для обоих вариантов)

#### 2. Управление состоянием
- **Файл**: `web/frontend/src/App.jsx`
- **Изменения**:
  - Добавлено состояние `algorithm` для управления выбором алгоритма
  - Созданы независимые состояния для каждого варианта:
    - `loadProfile` / `loadProfile_qp`
    - `parameters` / `parameters_qp`
    - `calculationResult` / `calculationResult_qp`
    - `isCalculating` / `isCalculating_qp`
    - `error` / `error_qp`
  - Реализовано условное отображение компонентов в зависимости от выбранного алгоритма

#### 3. Новые компоненты для QP варианта
Созданы копии всех компонентов с суффиксом `_qp`:

- `DataInputSection_qp.jsx` - Ввод исходных данных
- `DataVisualizationSection_qp.jsx` - Визуализация данных
- `ChartsSection_qp.jsx` - Графики результатов
- `SchematicSection_qp.jsx` - Схема системы
- `BatteryInteractiveSection_qp.jsx` - Интерактивный выбор параметров

**Особенности**:
- Все компоненты полностью независимы от WF версии
- Используются уникальные ID элементов (добавлен суффикс `-qp`)
- Заголовки помечены как "(QP)" для различения

#### 4. API сервис
- **Файл**: `web/frontend/src/services/api.js`
- **Добавлены функции**:
  - `calculateSchedule_qp()` - расчет графика (QP)
  - `calculateOptimalParameters_qp()` - расчет оптимальных параметров (QP)

### Backend

#### 1. Новые классы и функции
- **Файл**: `web/backend/energy_storage_calculator.py`
- **Добавлено**:
  - `EnergyStorageCalculator_qp` - класс для расчета графика (копия оригинального)
  - `calculate_optimal_parameters_qp()` - функция расчета оптимальных параметров

**Примечание**: На данном этапе QP версия является копией WF алгоритма. В дальнейшем алгоритмы расчета будут заменены на квадратичную оптимизацию.

#### 2. API endpoints
- **Файл**: `web/backend/main.py`
- **Добавлены endpoints**:
  - `POST /api/v1/calculate-qp` - расчет диспетчерского графика (QP)
  - `POST /api/v1/calculate-optimal-parameters-qp` - расчет оптимальных параметров (QP)

## Общие секции

Следующие секции остаются общими для обоих вариантов:
- `Hero` - заголовок и переключатель алгоритмов
- `Footer` - подвал страницы

## Независимые секции

Каждый вариант имеет свои независимые секции:

### Water-Filling вариант
- `DataInputSection`
- `DataVisualizationSection`
- `ChartsSection`
- `SchematicSection`

### QP вариант
- `DataInputSection_qp`
- `DataVisualizationSection_qp`
- `ChartsSection_qp`
- `SchematicSection_qp`
