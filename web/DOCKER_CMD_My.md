Базовые команды Docker
Проверка: docker version, docker info
Список контейнеров: docker ps (активные), docker ps -a (все)
Логи контейнера: docker logs <container> (с -f для tail)
Остановить/запустить: docker stop <container>, docker start <container>, docker restart <container>
Удалить контейнер: docker rm <container>
Список образов: docker images
Удалить образ: docker rmi <image>
Чистка: docker system prune (осторожно, удаляет неиспользуемое)

Docker Compose (если используете)

Запуск:
docker compose up -d
# создаёт контейнеры, если их ещё нет; может собрать образы (build) или скачать (pull); запускает контейнеры

docker compose start
# просто стартует ранее созданные контейнеры из down/stop;НЕ создаёт контейнеры; НЕ собирает образы 

Остановить:
docker compose down
# останавливает и удаляет контейнеры (и сеть, иногда тома) (удаляет контейнеры; удаляет созданные compose‑сеть(и); по умолчанию не удаляет тома (для томов нужен -v); можно быстро поднять только через docker compose up)

docker compose stop
# останавливает контейнеры (контейнеры остаются в системе;
можно быстро поднять docker compose start; образы, сети, тома не трогает)

docker compose rm
# удаляет остановленные контейнеры сервисов, созданные compose‑проектом.
Ключевые моменты:
контейнеры должны быть остановлены (иначе с -f).
образы не удаляет.
сети не удаляет.
тома не удаляет (если не указать -v).
Частые варианты:
docker compose rm — интерактивно спросит подтверждение.
docker compose rm -f — удалит без вопросов.
docker compose rm -f -v — удалит контейнеры и анонимные тома.

Пересобрать: docker compose up -d --build
Логи: docker compose logs -f

Качаем с Docker Hub:
docker-compose pull
#  скачивает образы для сервисов из реестра (Docker Hub, приватный registry) по полям image: в docker-compose.yml.
Ключевые детали:
тянет только образы, контейнеры не создаёт и не запускает
если у сервиса есть build:, но нет image:, тянуть нечего
по умолчанию тянет все сервисы, можно указать конкретные:
docker compose pull backend frontend

Создаем контейнеры:
docker compose up -d
# создаёт (если нужно), пересоздаёт и запускает контейнеры в фоновом режиме (detached).
Что делает по шагам:
читает docker-compose.yml
если контейнеров нет — создаёт
если образа нет — собирает (при build:) или скачивает (при image:)
запускает контейнеры в фоне (без вывода логов в терминал)
-d означает detached mode — запуск в фоне.
Команда сразу возвращает управление, а контейнеры продолжают работать.
Без -d выводятся логи в терминал, и процесс держит сессию открытой.
