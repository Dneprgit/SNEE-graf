# Миграция на scipy.optimize для квадратичной оптимизации

## Проблема

При использовании `alglib-cpython` расчет оценочных параметров выполнялся некорректно. Было принято решение вернуться к использованию C++ библиотеки `alglib`, расположенной в `web/QuickQPsource`.

## Сложность использования QuickQP.dll

QuickQP.dll экспортирует функцию:
```cpp
int __stdcall BLEICQPSolve(
    SAFEARRAY **mX, 
    SAFEARRAY **mA, 
    SAFEARRAY **mB, 
    SAFEARRAY **mC, 
    SAFEARRAY **mCL, 
    SAFEARRAY **mCU, 
    SAFEARRAY **mBndL, 
    SAFEARRAY **mBndU, 
    SAFEARRAY **mS, 
    SAFEARRAY **mX0
)
```

**Проблема**: `SAFEARRAY` - это COM-структура из Visual Basic, которую крайне сложно использовать напрямую из Python через `ctypes`. Для этого потребовалось бы:
1. Использовать `comtypes` или `win32com`
2. Создавать SAFEARRAY вручную через COM API
3. Управлять памятью COM-объектов

Это существенно усложняет код и может привести к утечкам памяти.

## Выбранное решение: scipy.optimize

Вместо использования сложного COM-интерфейса, был выбран подход с использованием **scipy.optimize.minimize** с методом **'trust-constr'**, который:

### Преимущества
1. ✅ **Чистый Python** - не требует DLL или COM
2. ✅ **Надежный** - метод trust-constr специально разработан для задач с ограничениями
3. ✅ **Совместимый** - работает на Windows/Linux/Mac
4. ✅ **Хорошо протестирован** - scipy широко используется в научных вычислениях
5. ✅ **Поддерживает те же типы ограничений**:
   - Box constraints (lb <= x <= ub)
   - Linear constraints (cl <= C'x <= cu)
   - Квадратичная целевая функция с градиентом и гессианом

### Математическая модель

Решается задача квадратичного программирования:

**Минимизировать**: `F(x) = 0.5 * x' * A * x + b' * x`

**При ограничениях**:
- `lb <= x <= ub` (box constraints)
- `cl <= C' * x <= cu` (linear constraints)

Где:
- `A` - симметричная положительно определенная матрица (n×n)
- `b` - вектор линейных коэффициентов (n)
- `C` - матрица линейных ограничений (k×n)
- `cl`, `cu` - границы линейных ограничений (k)
- `lb`, `ub` - границы переменных (n)

### Метод trust-constr

**trust-constr** - это метод доверительной области для задач с ограничениями:
- Эффективен для квадратичных задач
- Использует градиент и гессиан (которые для QP известны аналитически)
- Гарантирует выполнение ограничений на каждой итерации
- Робастен к плохим начальным приближениям

### Коды завершения

Scipy коды преобразуются в коды alglib для совместимости:

| Scipy результат | Код alglib | Описание |
|----------------|------------|----------|
| success (малое изменение X) | 2 | X(k+1)-X(k) is small enough |
| success (малый градиент) | 4 | Gradient is small enough |
| success (малое изменение F) | 1 | Function change is small enough |
| infeasible | -3 | Inconsistent constraints |
| unbounded | -4 | Function is unbounded from below |
| other failure | -2 | Difficulty finding feasible point |

## Реализация

### Файлы изменены

1. **`web/backend/quadratic_optimizer.py`**
   - Полностью переписан для использования scipy
   - Функция `solve_qp_problem()` теперь использует `minimize()` с trust-constr
   - Сохранена та же сигнатура для совместимости

2. **`web/backend/requirements.txt`**
   - Добавлена зависимость `scipy>=1.11.0`

3. **`web/backend/ppw_calculator.py`**
   - Без изменений - использует тот же интерфейс `solve_qp_problem()`

### Пример использования

```python
from quadratic_optimizer import solve_qp_problem
import numpy as np

# Задача: минимизировать (x1-1)^2 + (x2-2)^2
# F(x) = 0.5*x'*A*x + b'*x, где A = [[2, 0], [0, 2]], b = [-2, -4]

n = 2
k = 1

A = np.array([[2.0, 0.0], [0.0, 2.0]])
b = np.array([-2.0, -4.0])
C = np.array([[1.0, 1.0]])  # ограничение: x1 + x2 <= 3
cl = np.array([-np.inf])
cu = np.array([3.0])
lb = np.array([0.0, 0.0])
ub = np.array([np.inf, np.inf])
s = np.array([1.0, 1.0])
x0 = np.array([0.0, 0.0])

x, code = solve_qp_problem(n, k, A, b, C, cl, cu, lb, ub, s, x0)
print(f"Solution: {x}, termination code: {code}")
# Expected: x ≈ [1, 2] or near boundary x1+x2=3
```

Для проверки корректности расчетов:

2. Откройте фронтенд:

3. Перейдите на "Вариант 2 (PPW)"
4. Нажмите "Загрузить профиль по умолчанию"
5. Нажмите "Рассчитать график"
6. Сравните "Оценочные параметры" с ожидаемыми значениями

### Ожидаемые результаты

Для тестового профиля баланса (с дефицитом и избытком):
- Оптимальная входная мощность должна покрывать максимальный избыток
- Оптимальная выходная мощность должна покрывать максимальный дефицит
- Оптимальная емкость должна обеспечивать накопление энергии

## Альтернативные решения (если scipy не подходит)

### Вариант A: Компиляция собственной DLL
Создать упрощенную DLL-обертку над alglib, которая принимает указатели на обычные массивы double[], а не SAFEARRAY.

### Вариант B: CVXOPT
Использовать библиотеку CVXOPT, специализированную для выпуклой оптимизации:
```python
from cvxopt import matrix, solvers
# ... аналогичный интерфейс
```

### Вариант C: OSQP
Использовать OSQP (Operator Splitting QP solver) - очень быстрый специализированный QP-решатель:
```python
import osqp
# ... настройка задачи
```

## Заключение

Переход на scipy.optimize позволяет:
- Избежать сложностей с COM-интерфейсами
- Использовать проверенный и надежный решатель
- Сохранить кроссплатформенность
- Упростить развертывание (нет внешних DLL)

Если результаты все еще неудовлетворительны, проблема может быть в:
1. Формировании матриц A, b, C в `ppw_calculator.py`
2. Начальных приближениях
3. Самой математической модели

В этом случае необходимо сравнить промежуточные значения с оригинальным VB-кодом.
